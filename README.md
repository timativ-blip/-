# Exit Poll

Приложение интервьюера для браузера телефона. Сервер — Python / FastAPI, база — SQLite. Интерфейс — HTML/CSS/JavaScript, работает без сборки.

## Что уже работает

- Фамилия, имя, выбор ТИК и его УИК один раз в день по времени `Europe/Moscow`.
- Поиск участка по номеру или названию.
- Счётчики заполненных анкет и отказов за сегодня в этом браузере для текущего имени интервьюера.
- 11 партий в указанном порядке. «Яблоко» недоступно и в интерфейсе, и на сервере.
- Отдельные варианты «Испортил бюллетень» и красная кнопка «Отказался отвечать».
- Пол и возраст обязательны, **в том числе при отказе**.
- Проверка ответов → отправка → новая анкета.
- Сохранение в IndexedDB до сетевой отправки. Повторная отправка одной анкеты не создаёт дубль.
- Устанавливаемая PWA «Экзитполы»: открытие ранее загруженного приложения без интернета и отдельная проверка «Устройство готово к офлайн-работе».
- Очередь неотправленных анкет на телефоне; повторная отправка при возвращении связи, при открытии приложения и раз в 30 секунд, пока страница работает.
- Аварийная кнопка для каждой анкеты: формирует короткий SMS-код, открывает приложение сообщений или копирует код, если служебный номер ещё не задан.
- Передача из SQLite в Google Таблицы с повторными попытками.
- Защищённый дашборд координатора на `/dashboard`: сводка по Google Таблице, фильтры по дате, ТИК и УИК, результаты, демография, динамика и работа интервьюеров. Данные обновляются каждые 30 секунд.
- Настраиваемый HTTPS-адаптер исходящих SMS остаётся доступен серверу для будущих уведомлений координатора.
- Резервная копия локальных анкет в JSON.

## Статус этой версии

Приложение опубликовано на [Render](https://exit-poll-pw6y.onrender.com); пользователь подтвердил работу экспорта в Google Таблицу.

1. **ТИК и УИК:** 56 ТИК и 3 925 УИК из предоставленного файла «ТИК и УИК.pdf». См. [источник и импорт](PRECINCTS_SOURCE.md).
2. **Google:** серверный экспорт; ТИК добавлен в столбец M. Старые колонки сохраняют своё положение.
3. **SMS:** приложение умеет подготовить SMS с кодом конкретной анкеты. Для отправки на единый номер задайте `SMS_REQUEST_NUMBER`. Автоматический приём такого SMS и запись в Google Таблицу потребуют выбранного SMS-провайдера и его webhook.
4. **GitHub:** [timativ-blip/-](https://github.com/timativ-blip/-). Репозиторий не содержит заполненных анкет, базы данных и ключей доступа.
5. **Хостинг:** бесплатный Render. Локальная база временная; уже записанные строки Google сохраняются, но ещё не выгруженная серверная очередь может быть утрачена при перезапуске.

## Быстрый локальный запуск

Нужен Python 3.13 или 3.14.

```sh
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте `http://127.0.0.1:8000`. Локальная версия не требует кода команды и не отправляет SMS или данные в Google без настройки. По умолчанию анкеты хранятся в `data/exit_poll.sqlite3`.

Для Windows активируйте окружение командой `.venv\Scripts\activate`.

## Список ТИК и УИК

В `precincts.json` загружен список из PDF: 56 ТИК и 3 925 УИК. Формат:

```json
[
  {"id": "mo-uik-1259", "label": "УИК № 1259", "tik": "ТИК города Видное"}
]
```

Интервьюер выбирает ТИК, затем ищет по номеру и выбирает УИК только этой комиссии. При смене ТИК выбранный УИК сбрасывается. Сервер проверяет соответствие. ТИК и УИК видны в данных смены и сохраняются вместе с анкетой.

`id` — постоянный уникальный идентификатор. Источник, контрольная сумма и команда повторного импорта находятся в `PRECINCTS_SOURCE.md`. После обновления откройте приложение с интернетом и обновите страницу; если отображается старая форма, обновите ещё раз после загрузки новой версии. Анкеты в браузере не удаляются. Пользователям со старым демонстрационным участком нужно заново выбрать ТИК и УИК; прежние офлайн-анкеты принимаются.

## Google Таблицы

1. Создайте таблицу и отдельный пустой лист `Анкеты`.
2. В проекте Google Cloud включите Google Sheets API и создайте сервисный аккаунт.
3. Предоставьте адресу сервисного аккаунта право редактировать эту конкретную таблицу.
4. Сохраните JSON-ключ **вне репозитория** и подключите его как секрет сервера.
5. Передайте переменные окружения:

```sh
export GOOGLE_SPREADSHEET_ID='идентификатор-между-d-и-edit-в-ссылке'
export GOOGLE_SHEET_NAME='Анкеты'
export GOOGLE_APPLICATION_CREDENTIALS='/absolute/path/to/service-account.json'
```

Перезапустите сервер. Неотправленные анкеты из SQLite начнут выгружаться автоматически. Заголовки: ID, время заполнения, дата смены, фамилия и имя интервьюера, ID и название УИК, ответ, пол, возраст, ID смены, время получения сервером, ТИК (столбец M).

**Лист `Анкеты` принадлежит приложению:** используйте отдельные листы для анализа. Экспорт сначала читает ID из колонки A, обновляет строки с тем же ID и записывает новые анкеты после существующих строк. При ошибке чтения запись не выполняется. Это защищает ранее выгруженные данные после сброса локальной базы и предотвращает дубли при повторе запроса после таймаута.

В одну вкладку должен писать только один сервер с одним процессом экспорта (`--workers 1`). Не запускайте локальную копию и Render с экспортом в одну вкладку одновременно. Во время экспорта не изменяйте порядок строк вручную. Неотправленные данные временной SQLite по-прежнему могут потеряться при перезапуске бесплатного сервера.

Блок «Аномалии интервьюеров» на дашборде хранит статусы («Уточнена» / «Устранена» и комментарий) в отдельной вкладке `Аномалии` той же таблицы (имя — `GOOGLE_ANOMALY_SHEET_NAME`). Вкладка создаётся автоматически при первом закрытии аномалии; лист `Анкеты` при этом не затрагивается. Сервисному аккаунту достаточно уже выданного права редактировать таблицу.

Запись использует режим `RAW`: введённые имена не превращаются в формулы Google Sheets. Сообщение «Все анкеты переданы на сервер» означает надёжную запись в SQLite; оно **не подтверждает**, что Google уже принял строки. Ошибки Google видны в журнале сервера без содержания ответов и секретов.

## Офлайн-режим и SMS

При первом запуске откройте приложение с интернетом и дождитесь зелёного сообщения **«Устройство готово к офлайн-работе»**. Оно означает, что интерфейс, форма, оформление и список ТИК/УИК сохранены на этом телефоне. На Android приложение предложит установку на главный экран. На iPhone используйте «Поделиться» → «На экран Домой».

После этого приложение открывается без Render и без интернета. Каждая анкета сначала записывается в IndexedDB на телефоне. При сетевой ошибке на главном экране появляется очередь с кнопками:

- **Отправить через SMS** — открывает сообщения с уже заполненным служебным номером и коротким кодом анкеты;
- **Копировать** — копирует тот же код для ручной передачи координатору;
- **Попробовать снова** — сразу повторяет отправку на Render.

Пример аварийного кода:

```text
EP1 1259 11 2 2 2609161411 a890836729f24934ade089f3f87f4f7c 19be34a2
```

В коде находятся версия формата, номер УИК, ответ, пол, возрастная группа, время, полный ID анкеты и короткий ID смены. Русского текста нет, поэтому сообщение остаётся компактным. Анкета после открытия SMS не удаляется из локальной очереди: когда интернет появится, она всё равно синхронизируется с Render.

Задайте номер в Render:

```text
SMS_REQUEST_NUMBER=+79001234567
```

Пока номер не задан, кнопка автоматически копирует SMS-код. Само открытие SMS работает через сотовую сеть телефона и не требует доступа к Render. Получатель номера должен уметь передать текст входящего SMS в серверный webhook. Формат webhook зависит от выбранного провайдера, поэтому его подключение выполняется после выбора сервиса и номера.

Существующий серверный адаптер исходящих уведомлений можно использовать отдельно. Он должен принимать:

```http
POST https://your-sms-adapter.example/send
Authorization: Bearer <SMS_GATEWAY_TOKEN>
Content-Type: application/json

{"to":"+79000000000","text":"Текст опроса…","request_id":"уникальный-id"}
```

Ответ после принятия сообщения провайдером:

```json
{"accepted": true}
```

Настройте `SMS_GATEWAY_URL` и `SMS_GATEWAY_TOKEN`. Это **контракт адаптера**, а не обещание совместимости с любым SMS API без доработки. Учётные данные провайдера остаются на сервере. До подключения провайдера реальные SMS не отправляются.

Интервьюер открывает «Связь и SMS», вводит свой телефон и при желании включает автоматические запросы. Плохая связь определяется сетевой ошибкой или ответом проверки дольше 3 секунд. Между попытками для одного телефона — минимум 15 минут, включая неопределённые ошибки. Успешное принятие сервисом не гарантирует доставку оператором. Длинный русский текст может тарифицироваться как несколько SMS.

Не публикуйте токен SMS-провайдера в браузере или GitHub: он хранится только в переменной `SMS_GATEWAY_TOKEN` на сервере.

## Публичный запуск

### Render

В репозитории есть готовый `render.yaml`. На [Render](https://render.com/) выберите **New → Blueprint**, подключите GitHub-репозиторий `timativ-blip/-` и подтвердите `render.yaml`. Он создаёт Docker-сервис `exit-poll`, HTTPS-адрес, health check и постоянный диск для SQLite. Для реального сбора нужен план с persistent disk; бесплатный режим не подходит для надёжного хранения очереди.

В настройках сервиса добавьте `ACCESS_CODE`, `SESSION_SECRET` и `GOOGLE_SPREADSHEET_ID`. JSON-ключ Google добавьте как Secret File с путём `/etc/secrets/google-service-account.json`. Не вставляйте JSON-ключ в обычную переменную и не коммитьте его в GitHub. После первого деплоя откройте выданный `https://...onrender.com` адрес в телефоне.

Для пульта координатора добавьте отдельную секретную переменную `DASHBOARD_CODE` длиной не менее 12 символов. Не используйте код интервьюеров. После деплоя откройте `https://ваш-сервис.onrender.com/dashboard`. Дашборд читает лист `Анкеты` через уже подключённый сервисный аккаунт Google и кэширует результат на сервере примерно на 25 секунд, чтобы не расходовать квоту Google Sheets при каждом открытии страницы.

Render автоматически передеплоит сервис после push в `main`. В `precincts.json` уже загружен список из предоставленного PDF.

`APP_ENV=production` требует `ACCESS_CODE` длиной не менее 12 символов, `SESSION_SECRET` длиной не менее 32 символов и замены демонстрационных УИК официальными. Код доступа сообщает координатор. Имя и УИК всё равно запрашиваются ежедневно; код команды хранится в защищённой cookie до 30 дней. Используйте HTTPS: оно необходимо и для защищённой cookie, и для Service Worker. HTTP допустим только для проверки на localhost.

Файл `.env` автоматически не загружается. Передайте переменные средствами хостинга, оболочки или `docker --env-file`.

```sh
docker build -t exit-poll .
docker run --env-file .env -p 127.0.0.1:8000:8000 \
  -v exit-poll-data:/app/data \
  -v /secure/google-service-account.json:/run/secrets/google-service-account.json:ro \
  exit-poll
```

Секрет Google монтируйте только при подключении таблицы. Перед приложением настройте HTTPS reverse proxy. Передавайте корректные Host и X-Forwarded-Proto; доверяйте forwarded-заголовкам только от своего proxy. Запускайте один процесс сервера (`--workers 1`), как в Dockerfile. Для нескольких независимых серверов потребуются общая БД и координация экспортёра.

Не публикуйте `.env`, ключи Google, резервные копии, базу данных или реальные анкеты в GitHub. `.gitignore` исключает стандартные файлы секретов и данных. Общий код команды — минимальная защита пилотной версии; персональные учётные записи, роли и отзыв доступа отдельному интервьюеру пока не реализованы.

## Публикация кода на GitHub

Создайте пустой репозиторий и выполните из папки проекта, подставив собственный адрес:

```sh
git init -b main
git add .
git commit -m "Add mobile Exit Poll application"
git remote add origin https://github.com/YOUR_ACCOUNT/YOUR_REPOSITORY.git
git push -u origin main
```

Если локальный репозиторий уже создан, пропустите `git init`. GitHub Actions запускает тесты при push и pull request. Для получения публичной ссылки на само приложение подключите этот репозиторий к Python/Docker-хостингу с постоянным диском, задайте секреты и HTTPS.

В подготовленной локальной копии уже настроен `origin`; после авторизации достаточно `git push -u origin main`. В ZIP-архиве папки `.git` нет — для него используйте полный порядок выше.

## Базовые данные 2021 (дашборд)

`app/baseline_2021.json` — итоги партийных списков Госдумы 2021 по 12 одномандатным округам Московской области (№118–129): число избирателей, явка и голоса по партиям. Источник — открытые данные ЦИК России ([сводные результаты, XML](http://www.cikrf.ru/opendata/84.xml)). Файл собирается скриптом `python scripts/import_baseline_2021.py` из корня репозитория и лежит в Git, сеть при запуске сервера не нужна.

`app/static/tik_map.json` — упрощённые границы 56 территорий ТИК для картограммы на дашборде. Источник — © участники OpenStreetMap, лицензия ODbL (ссылка на источник выводится под картой). Файл собирается скриптом `python scripts/build_tik_map.py` из корня репозитория (нужны `pip install requests shapely`, только для сборки; запросы к Overpass API идут медленно, промежуточные ответы кэшируются в `/tmp/tik_map_cache`) и лежит в Git. Явка 2026 по ТИК в открытых источниках не публикуется, поэтому слой «Явка 2021» на карте показывает итоги Госдумы 2021 по округам.

Он используется тремя способами: теплокарта «Динамика к 2021» (опрос минус итоги 2021 по округам, доли пересчитаны на те же партии, что в опросе), колонка «2021» на вкладке «Прогноз» и вес территорий в прогнозе (электорат округа 2021 года, внутри округа делится между ТИК по числу УИК). Данные ЦИК агрегированы до округов; данных по ТИК и УИК в открытом доступе нет, поэтому 2021 год — только ориентир: список партий и способ голосования (ДЭГ) изменились.

Справка об охвате потока (`FLOW_CONTEXT` в `app/main.py`) — датированный снимок явки по новостям за 18.09.2026 (РИА Новости, 360.ru); сама она не обновляется.

## Проверки

```sh
pip install -r requirements-dev.txt
python -m pytest -q
```

Тесты проверяют все варианты ответов, обязательность пола/возраста при отказе, запрет «Яблока», неизвестный УИК, даты офлайн-анкет, защиту от дублей и конфликтующих ID, повтор записи в Google после таймаута, режим RAW, доступ по коду и запрет межсайтовой отправки.

Также проверен браузерный цикл на ширине 390 px: начало смены, выбор партии, пол/возраст, проверка, отправка и счётчики. При выключенном сервере приложение повторно открылось из кеша, сохранило отказ с полом/возрастом и пережило перезагрузку. После включения сервера очередь отправилась автоматически; в SQLite остались ровно две тестовые записи — одна анкета и один отказ.

## Ограничения офлайн-режима

- Первый запуск требует интернета. Дождитесь сообщения «Устройство готово к офлайн-работе» и заранее откройте установленное приложение в авиарежиме.
- Очередь хранится в конкретном браузере и устройстве; другой телефон не увидит её и локальные счётчики.
- Не используйте приватный режим и не очищайте данные сайта до отправки. ОС может удалить данные сайта при нехватке места, несмотря на запрос постоянного хранения.
- Закрытый браузер не гарантирует фоновой отправки: откройте приложение после восстановления связи.
- Дата определяется часами телефона в часовой зоне исследования. Неверные часы требуют исправления.
- Заполненный черновик сохраняется при перезагрузке в пределах дня. При новом дне начинается новая смена; незавершённый вчерашний черновик сбрасывается. Уже сохранённые вчерашние анкеты остаются в очереди.
- Резервная копия JSON доступна координатору для восстановления, но автоматический импорт в интерфейсе пока не реализован.
- Перед реальным полевым запуском проведите проверку на используемых Android/iPhone, нагрузочное испытание и тест с реальными Google/SMS-подключениями.
