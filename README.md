# Exit Poll

Приложение интервьюера для браузера телефона. Сервер — Python / FastAPI, база — SQLite. Интерфейс — HTML/CSS/JavaScript, работает без сборки.

## Что уже работает

- Фамилия, имя и выбор УИК один раз в день по времени `Europe/Moscow`.
- Поиск участка по номеру или названию.
- Счётчики заполненных анкет и отказов за сегодня в этом браузере для текущего имени интервьюера.
- 11 партий в указанном порядке. «Яблоко» недоступно и в интерфейсе, и на сервере.
- Отдельные варианты «Испортил бюллетень» и красная кнопка «Отказался отвечать».
- Пол и возраст обязательны, **в том числе при отказе**.
- Проверка ответов → отправка → новая анкета.
- Сохранение в IndexedDB до сетевой отправки. Повторная отправка одной анкеты не создаёт дубль.
- Открытие ранее загруженного приложения без интернета; повторная отправка при возвращении связи, при открытии приложения и раз в 30 секунд, пока страница работает.
- Передача из SQLite в Google Таблицы с повторными попытками.
- Настраиваемый запрос SMS-памятки через HTTPS-адаптер, кнопка ручного запроса и согласие на автоматический запрос при слабой связи.
- Резервная копия локальных анкет в JSON.

## Статус этой версии

Это запускаемая тестовая версия, пока без внешних подключений.

1. **УИК:** в `precincts.json` три явно помеченных демонстрационных участка. 15.09.2026 официальный сайт ИКМО `http://www.moscow_reg.izbirkom.ru/` не открылся через поиск и браузер. Полный актуальный перечень Московской области не получен. Демонстрационные номера нельзя использовать для реального исследования.
2. **Google:** модуль экспорта реализован, ссылка на таблицу получена; учётные данные для серверной записи не предоставлены. Экспорт проверен на тестовом приёмнике, реальная запись в Google пока не проверена.
3. **SMS:** реализован контракт подключения; коммерческий провайдер не выбран и не подключён. SMS содержит текст опроса; входящие ответы по SMS эта версия не принимает.
4. **GitHub:** исходники проекта размещаются в репозитории [timativ-blip/-](https://github.com/timativ-blip/-). Код не содержит заполненных анкет, базы данных или ключей доступа.
5. **Хостинг:** для публичной ссылки нужен сервер с HTTPS и постоянным диском. GitHub хранит код; GitHub Pages обслуживает статические сайты и не запускает Python-сервер.

## Быстрый локальный запуск

Нужен Python 3.13 или 3.14.

```sh
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте `http://127.0.0.1:8000`. Локальная версия не требует кода команды и не отправляет SMS или данные в Google без настройки. По умолчанию анкеты хранятся в `data/exit_poll.sqlite3`.

Для Windows активируйте окружение командой `.venv\Scripts\activate`.

## Список УИК

Замените `precincts.json` официальной выгрузкой. Формат:

```json
[
  {"id": "50-REAL_NUMBER", "label": "УИК № REAL_NUMBER · муниципалитет · адрес"}
]
```

`id` — постоянный уникальный идентификатор, `label` — отображаемое название. Добавьте в файл `PRECINCTS_SOURCE.md` источник, дату документа и дату проверки. После обновления перезапустите сервер; телефоны должны открыть приложение с интернетом, чтобы получить список. Не удаляйте ID старых участков до отправки всех офлайн-анкет: сервер проверяет принадлежность УИК справочнику.

## Google Таблицы

1. Создайте таблицу и отдельный пустой лист `Анкеты`.
2. В проекте Google Cloud включите Google Sheets API и создайте сервисный аккаунт.
3. Предоставьте адресу сервисного аккаунта право редактировать эту конкретную таблицу.
4. Сохраните JSON-ключ **вне репозитория** и подключите его как секрет сервера.
5. Передайте переменные окружения:

```sh
export GOOGLE_SPREADSHEET_ID='идентификатор-между-d-и-edit-в-ссылке'
export GOOGLE_SHEET_NAME='Анкеты'
export GOOGLE_APPLICATION_CREDENTIALS='/absolute/path/to/service-account.json'
```

Перезапустите сервер. Неотправленные анкеты из SQLite начнут выгружаться автоматически. Заголовки: ID, время заполнения, дата смены, фамилия и имя интервьюера, ID и название УИК, ответ, пол, возраст, ID смены, время получения сервером.

**Лист `Анкеты` принадлежит приложению:** не сортируйте физически строки, не вставляйте/удаляйте строки, не пишите в него другим приложением. Для анализа используйте другой лист или представления фильтра. Приложение записывает каждую анкету в постоянный номер строки, поэтому после неопределённого сетевого таймаута повторяет ту же запись. Это предотвращает дубли от повторного добавления строки.

Одна база SQLite должна соответствовать одному листу. Не подключайте несколько независимых серверов/баз к одному листу. Не удаляйте базу при обновлении приложения. Восстановление старой копии базы при наличии более новых строк в Google требует сверки координатором.

Запись использует режим `RAW`: введённые имена не превращаются в формулы Google Sheets. Сообщение «Все анкеты переданы на сервер» означает надёжную запись в SQLite; оно **не подтверждает**, что Google уже принял строки. Ошибки Google видны в журнале сервера без содержания ответов и секретов.

## SMS при плохом интернете

Полный обрыв интернета не позволяет браузеру послать команду SMS-сервису. Основной резерв — офлайн-анкеты. SMS-памятка полезна, когда интернет нестабилен, но запрос до сервера ещё проходит.

Адаптер вашего SMS-провайдера должен принимать:

```http
POST https://your-sms-adapter.example/send
Authorization: Bearer <SMS_GATEWAY_TOKEN>
Content-Type: application/json

{"to":"+79000000000","text":"Текст опроса…","request_id":"уникальный-id"}
```

Ответ после принятия сообщения провайдером:

```json
{"accepted": true}
```

Настройте `SMS_GATEWAY_URL` и `SMS_GATEWAY_TOKEN`. Это **контракт адаптера**, а не обещание совместимости с любым SMS API без доработки. Учётные данные провайдера остаются на сервере. До подключения провайдера реальные SMS не отправляются.

Интервьюер открывает «Связь и SMS», вводит свой телефон и при желании включает автоматические запросы. Плохая связь определяется сетевой ошибкой или ответом проверки дольше 3 секунд. Между попытками для одного телефона — минимум 15 минут, включая неопределённые ошибки. Успешное принятие сервисом не гарантирует доставку оператором. Длинный русский текст может тарифицироваться как несколько SMS.

`SMS_REQUEST_NUMBER` можно задать только после подключения номера, который действительно принимает слово `EXITPOLL` и отправляет памятку в ответ. Приложение открывает SMS-композер; интервьюер отправляет сообщение сам. Приём входящих SMS и обмен вопросами/ответами требуют отдельной интеграции с выбранным провайдером. Здесь она не реализована.

## Публичный запуск

`APP_ENV=production` требует `ACCESS_CODE` длиной не менее 12 символов, `SESSION_SECRET` длиной не менее 32 символов и замены демонстрационных УИК официальными. Код доступа сообщает координатор. Имя и УИК всё равно запрашиваются ежедневно; код команды хранится в защищённой cookie до 30 дней. Используйте HTTPS: оно необходимо и для защищённой cookie, и для Service Worker. HTTP допустим только для проверки на localhost.

Файл `.env` автоматически не загружается. Передайте переменные средствами хостинга, оболочки или `docker --env-file`.

```sh
docker build -t exit-poll .
docker run --env-file .env -p 127.0.0.1:8000:8000 \
  -v exit-poll-data:/app/data \
  -v /secure/google-service-account.json:/run/secrets/google-service-account.json:ro \
  exit-poll
```

Секрет Google монтируйте только при подключении таблицы. Перед приложением настройте HTTPS reverse proxy. Передавайте корректные Host и X-Forwarded-Proto; доверяйте forwarded-заголовкам только от своего proxy. Запускайте один процесс сервера (`--workers 1`), как в Dockerfile. Для нескольких независимых серверов потребуются общая БД и координация экспортёра.

Не публикуйте `.env`, ключи Google, резервные копии, базу данных или реальные анкеты в GitHub. `.gitignore` исключает стандартные файлы секретов и данных. Общий код команды — минимальная защита пилотной версии; персональные учётные записи, роли и отзыв доступа отдельному интервьюеру пока не реализованы.

## Публикация кода на GitHub

Создайте пустой репозиторий и выполните из папки проекта, подставив собственный адрес:

```sh
git init -b main
git add .
git commit -m "Add mobile Exit Poll application"
git remote add origin https://github.com/YOUR_ACCOUNT/YOUR_REPOSITORY.git
git push -u origin main
```

Если локальный репозиторий уже создан, пропустите `git init`. GitHub Actions запускает тесты при push и pull request. Для получения публичной ссылки на само приложение подключите этот репозиторий к Python/Docker-хостингу с постоянным диском, задайте секреты и HTTPS.

В подготовленной локальной копии уже настроен `origin`; после авторизации достаточно `git push -u origin main`. В ZIP-архиве папки `.git` нет — для него используйте полный порядок выше.

## Проверки

```sh
pip install -r requirements-dev.txt
python -m pytest -q
```

Тесты проверяют все варианты ответов, обязательность пола/возраста при отказе, запрет «Яблока», неизвестный УИК, даты офлайн-анкет, защиту от дублей и конфликтующих ID, повтор записи в Google после таймаута, режим RAW, доступ по коду и запрет межсайтовой отправки.

Также проверен браузерный цикл на ширине 390 px: начало смены, выбор партии, пол/возраст, проверка, отправка и счётчики. При выключенном сервере приложение повторно открылось из кеша, сохранило отказ с полом/возрастом и пережило перезагрузку. После включения сервера очередь отправилась автоматически; в SQLite остались ровно две тестовые записи — одна анкета и один отказ.

## Ограничения офлайн-режима

- Первый запуск требует интернета. Дождитесь полной загрузки до выхода на участок.
- Очередь хранится в конкретном браузере и устройстве; другой телефон не увидит её и локальные счётчики.
- Не используйте приватный режим и не очищайте данные сайта до отправки. ОС может удалить данные сайта при нехватке места, несмотря на запрос постоянного хранения.
- Закрытый браузер не гарантирует фоновой отправки: откройте приложение после восстановления связи.
- Дата определяется часами телефона в часовой зоне исследования. Неверные часы требуют исправления.
- Заполненный черновик сохраняется при перезагрузке в пределах дня. При новом дне начинается новая смена; незавершённый вчерашний черновик сбрасывается. Уже сохранённые вчерашние анкеты остаются в очереди.
- Резервная копия JSON доступна координатору для восстановления, но автоматический импорт в интерфейсе пока не реализован.
- Перед реальным полевым запуском проведите проверку на используемых Android/iPhone, нагрузочное испытание и тест с реальными Google/SMS-подключениями.
